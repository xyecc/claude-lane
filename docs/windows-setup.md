## 阶段 ②：装软件（对方自己做，D-1）

### W01–W02 下载安装 Clash Verge Rev

- 打开 https://github.com/clash-verge-rev/clash-verge-rev/releases ，下载最新版里名字含 **`x64-setup.exe`** 的那个（ARM 电脑选 `arm64-setup.exe`；⚠️ 打不开安装界面的老系统选带 `fixed_webview2` 的版本）。
- 双击安装。Windows 弹「已保护你的电脑」→ 点「更多信息」→「仍要运行」。
- 做对了：桌面出现 Clash Verge 图标，打开是深色/浅色的主界面，左侧有「代理 / 订阅 / 连接 / 规则 / 日志 / 设置」。
- 📷 W01 · 📷 W02

### W03 导入机场订阅

- 左侧「订阅」→ 顶部输入框粘贴机场给的订阅链接 →「导入」。
- 做对了：出现一张带机场名的卡片，**点一下卡片**让它高亮（=已激活）；左侧「代理」页能看到一堆节点。
- 📷 W03

### W04 开服务模式 + TUN，保持规则模式

- 左侧「设置」→ **服务模式**：打开（会弹 UAC 管理员确认，点是；⚠️ 若提示安装服务失败，先退出所有其他代理软件再试）→ **TUN 模式**：打开。
- 「代理」页顶部的模式选 **规则**（不要全局、不要直连）。
- 做对了：两个开关都是打开状态，TUN 没有红色报错。
- 📷 W04

### W05 验收（截图发协助者）

- 浏览器打开 https://api.ipify.org ——显示的应该是一个**国外 IP**（机场节点），不再是你本地的 IP。
- 📷 W05

> ⚠️ 电脑上如果装过 Clash for Windows / v2rayN / Shadowrocket 等其他代理软件，**必须退出**（最好卸载）——两个代理抢路由是本方案第一红线，症状从规则失效到整机断网都有。

## 阶段 ③：配置（协助者在线，≈20 分钟）

先做一份手工备份：打开资源管理器地址栏输入 `%APPDATA%\io.github.clash-verge-rev.clash-verge-rev`（⚠️ 路径待真机确认），把 `profiles` 文件夹整个复制到桌面。搞砸了复制回去、点一下卡片就是回滚。

### W06 找到四个编辑器

- 「订阅」页 → **右键**当前订阅卡片 → 菜单里有「编辑节点 / 编辑分组 / 编辑规则 / 编辑 Merge」四项，对应本仓库 `templates/` 的模板①②③④。
- 📷 W06

### W07 编辑节点 ← 模板①（凭证由机主自己填）

- 打开「编辑节点」，把 `templates/1-proxies.yaml` 的内容粘进去，**机主自己**把《静态IP主机》《端口》《用户名》《密码》四处换成真实值（协助者不看屏幕这一步）。`type: socks5`、`udp: false`、`dialer-proxy: "US-Chain"` 三行**一个字不能改**。保存。
- 做对了：保存后没有 YAML 报错提示。
- 📷 W07（凭证打码）

### W08–W09 编辑分组 ← 模板②

- 先去「代理」页，把订阅里 2–3 个**美国节点的名字原样复制**（含 emoji、空格、倍率后缀，逐字一致）。📷 W08
- 打开「编辑分组」，粘 `templates/2-groups.yaml`，把 `US-Chain` 下面的《美国节点1/2/3》换成刚复制的名字（延迟低的放前面）。保存。📷 W09

### W10 编辑规则 ← 模板③（Windows 进程名版）

- 打开「编辑规则」，粘 `templates/3-rules.yaml`，然后做 Windows 替换：
  - 两行 Chrome 的 QUIC 拦截：`Google Chrome Helper` 和 `Google Chrome` 都改成 **`chrome.exe`**（Edge 用 `msedge.exe`）
  - Claude 桌面版：在原有 `Claude` 各行旁边**再加一份 `Claude.exe`** 的同样规则（UDP 拒绝一条 + 导流一条）；`claude.exe`（Claude Code）保持不动
  - 其余域名 / IP 段规则原样，**顺序不动**，QUIC 拦截仍在最前
- ⚠️ 进程名以真机为准：激活后打开 Claude 用一下，到「连接」页看每条连接显示的进程名，凡是 Claude 相关却没走 `Claude` 组的，把它的进程名照样式补一条规则。
- 📷 W10

### W11 编辑 Merge ← 模板④

- 粘 `templates/4-merge.yaml` 的 sniffer 段。保存。📷 W11

### W12 激活并查日志

- 回到「订阅」页，**点一下**当前订阅卡片（重新合并 + 内核加载）。
- 「日志」页没有 `Start TUN listening error` 之类红色报错。有 `add route ... file exists` → 有别的 VPN 占路由，见排障手册第 1 条。
- 「代理」页多出 `Claude` 和 `US-Chain` 两个组：`Claude` 指向 `🇺🇸 US-Static`，`US-Chain` 指向某个美国节点。
- 📷 W12

### W13–W14 验收（两条都要对）

| 打开 | 期望 |
|---|---|
| `https://claude.ai/cdn-cgi/trace` | `ip=` 那行 **等于静态 IP** |
| `https://api.ipify.org` | **等于机场节点 IP**，≠ 静态 IP（证明没全局误走静态） |

再看「连接」页：claude.ai / anthropic.com 的连接，链路显示经过 `Claude` 组和 `US-Static`；其他网站不经过。📷 W13 · 📷 W14

## 阶段 ④：收尾（机主自己）

- **完全退出**再打开 Chrome 和 Claude 桌面版：关窗口没用，要在任务栏托盘右键 → 退出（QUIC/连接有缓存）。📷 W15
- 已有 Claude 账号的：claude.ai → 设置 → 帐户 → 活跃会话，撤销归属地不是静态 IP 所在地的旧会话，重新登录；还没账号的现在再去注册（线搭好之后才注册，账号从第一天起只见过一个 IP）。
- 系统地区建议改成美国：设置 → 时间和语言 → 区域 → 国家或地区：美国（界面语言不用动）。
- 三条红线：不装第二个 VPN；保持规则模式；改完配置要完全退出重启 Chrome / Claude。

## 出问题

- 症状对照 `troubleshooting.md`（第 1、2、8、10 条在 Windows 上同样适用）。
- 回滚：把桌面上备份的 `profiles` 文件夹复制回原位，点一下订阅卡片。
