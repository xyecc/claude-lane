## 1. 踩坑实录

### 坑 1：干净 macOS 的「隐形依赖」——今晚最大的时间黑洞

macOS 上 `/usr/bin/git` 和 `/usr/bin/python3` 都是 **Xcode 命令行工具（CLT）的壳命令**。任何程序调用一下，系统就弹「Install Command Line Developer Tools」安装框（1.5 GB 起步）。

今晚被弹了**三次**：Codex 执行 `git clone` 时、Grok 启动探测 git 状态时、Grok 调用 `python3` 解析配置时。

**结论 A — `git` 完全不需要。** 用 curl 下载 zip 代替 clone（`curl` / `unzip` 都是 macOS 自带，不依赖 CLT）：

```bash
cd ~ && curl -fL https://codeload.github.com/maien210/claude-lane/zip/refs/heads/main \
  -o claude-lane.zip && unzip -oq claude-lane.zip && rm -rf claude-lane \
  && mv claude-lane-main claude-lane && cd claude-lane && ls
```

**结论 B — `python3` 是真依赖，但不必装 CLT。**
`scripts/verify.sh` 有 8 处、`scripts/set-credentials.sh` 有 4 处调用 python3，绕不过去。但装 python.org 官方包只要 **65 MB**（装完约 150 MB），比 CLT 省十倍：

```bash
curl --http1.1 -fL --progress-bar \
  https://www.python.org/ftp/python/3.13.15/python-3.13.15-macos11.pkg \
  -o ~/Downloads/python3.pkg
sudo installer -pkg ~/Downloads/python3.pkg -target /
/usr/local/bin/python3 --version    # 验证
rm ~/Downloads/python3.pkg          # 省空间
```

⚠️ **`CLAUDE.md` Phase 0 目前写的建议是 `xcode-select --install`，应改成上面这条。**

**结论 C —** agent 启动时习惯性探测 git 触发的弹框，**点「停止」即可**，不影响后续。可能会弹多次。

### 坑 2：代理环境下载大文件必炸

Grok 的 `install.sh`（`https://x.ai/cli/install.sh`）内部用 **8 路并发 range 请求**分块下载。经 Clash 的 HTTP/2 必崩：

```
curl: (92) HTTP/2 stream 1 was not closed cleanly before end of the underlying stream
```

而且它会**无限重试**，加上 `-fsSL` 的 `s` 是 silent，**连进度都看不到**，现场只能干等，极其煎熬。

**解药（记住这三个参数，代理下任何大文件都用）：**

```bash
curl --http1.1 -C - --progress-bar
```

- `--http1.1` 避开 HTTP/2 崩流
- `-C -` 断点续传（断了重跑同一条命令接着下）
- `--progress-bar` 看得见进度

**Grok 手动安装完整流程**（绕开 install.sh 的并发逻辑）：

```bash
# 1) 单流下载（备用源：https://storage.googleapis.com/grok-build-public-artifacts/cli/…）
mkdir -p ~/.grok/downloads ~/.grok/bin && \
curl --http1.1 -C - -fL --progress-bar \
  https://x.ai/cli/grok-1.0.0-macos-aarch64 \
  -o ~/.grok/downloads/grok-macos-aarch64

# 2) 挂成命令
chmod +x ~/.grok/downloads/grok-macos-aarch64 && \
ln -sf ../downloads/grok-macos-aarch64 ~/.grok/bin/grok && \
ln -sf ../downloads/grok-macos-aarch64 ~/.grok/bin/agent && \
echo 'export PATH="$HOME/.grok/bin:$PATH"' >> ~/.zshrc && \
export PATH="$HOME/.grok/bin:$PATH" && grok --version
```

> 文件已完整时再跑带 `-C -` 的下载命令会报 `curl: (22) … error: 416`——那是「没得续了」，**无害**，说明文件是好的。

### 坑 3：卡住的从来不是 agent，是环境

今晚在「用 Claude Code / Grok / Codex」上绕了一个多小时，三个都试了。**结果三者会卡在完全相同的 Xcode 弹框上。**

**换 agent 解决不了依赖问题。** 正确顺序是：先体检铺平依赖 → 再选 agent。

附各 agent 的实际观感：

| Agent | 观察 |
|---|---|
| **Grok CLI** | 单二进制、不吃内存、最终跑通。Phase 0 质量不错（自动找出 12 个美国节点、正确识别缺 python3 就拒绝进 Phase 1） |
| **Codex 桌面版** | 吃内存，老机器扛不住；且被 git 依赖挡住 |
| **Claude Code** | 需登录 Claude 账号（或挂第三方 API），本场景其实完全可用，见坑 4 |

### 坑 4：账号顾虑绕了远路

一开始按 Windows 那轮的思路推「Claude Code 挂 DeepSeek API、零 OAuth」。**但那套是为「我自己的测试机、配完就撤、不想留授权」设计的。**

给朋友装机场景完全不同：**机器是他的、账号是他的、配完他天天用。** 让机主登自己的账号才是正解。

（备查：Claude Code 挂 DeepSeek 的配置形态 —— `ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic`、`ANTHROPIC_AUTH_TOKEN=<key>`、`ANTHROPIC_MODEL` 及三个 `ANTHROPIC_DEFAULT_*_MODEL` 全设成 `deepseek-v4-flash`，另设 `CLAUDE_CONFIG_DIR` 到临时目录以免留痕。**此场景用不上，留作他用。**）

### 坑 5：相邻命令长得像，导致重跑

「下载」和「安装」分成两块给，机主重跑了下载那条，撞出 416，白折腾一轮。

**教训（给协助者自己的）**：相邻命令若形似，要么合成一条，要么明确标注「这条和上一条不一样」。

### 坑 6：秘密两次进了 AI 对话

截图把静态 IP 的地址 / 端口 / 用户名带进了对话（密码是隐藏输入，未泄露）。Windows 那轮一次，本轮又一次。

**规矩**：远程协助**先关掉远程软件的剪贴板同步**；机主截图前**切走含凭证的标签页**（ISP 后台、IP 归属地查询页、Clash 订阅页都会带）。已泄露就去服务商后台轮换凭证。

### 坑 7：Grok / Codex 不会自动读 `CLAUDE.md`

它们找的是 `AGENTS.md` / `GROK.md`。**提示词里必须明确点名**「完整读取 CLAUDE.md，不是 AGENTS.md，本仓库没有 AGENTS.md」，否则它不知道手册在哪。

### 坑 8：README 的前提在干净机器上不成立

README 写「前提：Claude Code 已安装、能正常对话」。但这台机器 **Claude Code / Node / git / python3 全都没有**——四个前提一个不满足。

「agent 一键」这个承诺，**对干净机器是打折的**（详见第 4 节）。

## 2. 有效的做法（下次直接复用）

### 2.1 给 agent 的提示词要带「本机已知状态」

实测非常有效 —— Grok 据此**直接跳过 Phase -1**，省一大截往返。模板：

```
本机已知状态，不用重新探测，Phase -1 跳过，直接从 Phase 0 开始：
- Clash Verge Rev <版本> 已装，机场订阅已导入，配置目录 <路径>
- /Applications 里有 <X>.app，另有 <Y>/<Z> 两个 VPN 配置，当前均未连接
- 本机没有 git、没装 Xcode 命令行工具。需要下载一律用 curl，绝对不要触发 xcode-select --install
- Claude Code 未安装，本流程不需要它
```

### 2.2 提示词里标【停】，让 agent 一口气跑到停点

不要每步都确认（那正是脚本版被否掉的体验）。只在**四个真正需要人的地方**停：

1. 增强文件就绪 → 机主自己跑 `set-credentials.sh` 隐藏输入四元组
2. 凭证写完 → 机主在 Clash 订阅页**点一下订阅卡片**
3. 六项验证有 FAIL 且同一项修三次不过 → 停下说明卡点
4. 全绿后 → 出最终报告（打码出口、用了几个美国节点、六项结果）

### 2.3 机主本人必须动手的，就 4 处

| 顺序 | 干什么 |
|---|---|
| ① | 另开终端，`export CLAUDE_LANE_DEPLOY_ID=<agent 给的 id>`，跑 `bash scripts/set-credentials.sh`，**分四次隐藏输入四元组**（主机只填 IP） |
| ② | 回复 agent「凭证已写入」 |
| ③ | Clash Verge → 订阅页 → **点一下当前订阅卡片**（必须点，写完文件不点等于没装） |
| ④ | claude.ai → 设置 → 帐户 → 活跃会话，**撤销归属地不对的旧会话，重新登录** |

①那步**把键盘还给机主本人**。

## 3. iPhone（小火箭）实测配方 —— 补 `docs/iphone-notes.md` 的缺口

`docs/iphone-notes.md` 至今写着「步骤没整理」。以下配方从**机主自己跑通的配置**逆推得出，**已验证可用**。

### 3.1 关键：链式那一跳，小火箭叫「代理通过」

对应 mihomo 的 `dialer-proxy`。这是整个 iOS 配置里唯一说不清、也最容易卡住的字段。

### 3.2 静态节点（首页 → 右上 `+`）

| 字段 | 值 |
|---|---|
| 类型 | **Socks5** |
| 地址 / 端口 / 用户 / 密码 | 四元组 |
| 算法 | auto |
| 插件 | none |
| TCP 快速打开 | **关** |
| **UDP 转发** | **关**（防 QUIC 漏流的一环，对应模板里的 `udp: false`） |
| **代理通过** | **选一个机场美国节点** ← 链式就靠它 |
| 备注 | 例如 `iproyal-静态住宅` |

**搭对了的标志**：节点列表里该节点显示成 **`SOCKS5 > SHADOWSOCKS`**（有箭头 = 链已成立），且它归到首页的「**本地节点**」分组下。

### 3.3 规则（配置 → 当前 `.conf` → 编辑 → 规则 → 右上 `+`）

只需两条，加完**拖到规则列表最顶端**（别被前面的规则截胡）：

| 类型 | 域名 | 策略 |
|---|---|---|
| `DOMAIN-KEYWORD` | `claude` | **LOCAL-SERVERS** |
| `DOMAIN-KEYWORD` | `anthropic` | **LOCAL-SERVERS** |

「扩展匹配」「预匹配」两个开关都保持**关**。

> `LOCAL-SERVERS` 就是「本地节点」那个组，静态节点在里面。
> 两条 keyword 已覆盖 claude.ai / claude.com / claudeusercontent.com / anthropic.com 全套，不必再加 DOMAIN-SUFFIX。
> 可选兜底：`IP-CIDR` `160.79.104.0/23` → LOCAL-SERVERS（Anthropic 自有段，DNS 被污染时用）。

### 3.4 验收（必做，两条都要对）

Safari 里依次打开：

| 地址 | 期望 |
|---|---|
| `https://claude.ai/cdn-cgi/trace` | 返回里的 `ip=` **等于静态 IP** |
| `https://api.ipify.org` | **等于机场节点 IP**，≠ 静态 IP |

第二条尤其重要 —— 它证明**没有全局误走静态 IP**（住宅 IP 带宽小、流量贵，全走上去会很难受）。

### 3.5 iOS 天然做不到的

**无进程级分流能力。** Mac 版那套「按进程名圈住 Claude / Claude Helper」和「只拒浏览器的 QUIC」在手机上都不存在，只能做**域名 + IP 两层**。够用，但比 Mac 糙。

### 3.6 红线不变

**Mac 上不要装 Shadowrocket**（会和 Clash Verge 抢系统路由）。**手机版没有这个问题**，手机小火箭 + Mac Clash 可同时用、互不干扰。多台设备**共用同一个静态 IP 是推荐做法**。

## 4. 一个更根本的发现

**本项目的「agent 一键」承诺，对干净机器是不成立的。**

README 的前提是「Claude Code 已能对话」+ git + python3 都在。今晚这台 Mac，**三个前提一个都不满足**，于是「一键」变成了两小时。

值得注意的是：

- **侧分支 `codex/bootstrap-v1.3.0` 的 `bootstrap.sh` 干的正是「依赖铺平」** —— 也就是今晚最痛的那部分；
- **main 的 agent 体验解决的是「配置」那部分。**

今晚的实证是：**干净机器上，这两件事都需要。**

2026-08-08 那个「脚本/检查点版永久留侧分支、不并 main」的决策**没有错**（那套一步一确认的体验确实糟糕，也是被否掉的原因）。但今晚说明 **main 缺一个轻量的 preflight** —— 不需要把整个 bootstrap 搬过来，只要一个**纯 bash、零依赖**的体检+补依赖脚本就够。

> 这是新证据，最终决策由维护者拍板。

## 6. 安全待办（机主/维护者本人）

1. **轮换 ISP 四元组** —— 本轮截图两次把地址/端口/用户名带进 AI 对话。去 IPRoyal 后台改密码或换凭证；换完 **Mac 和 iPhone 各重填一遍**（Mac 上先 `rollback` 再重跑 routing/`set-credentials.sh`）。新凭证只存密码管理器。
2. **claude.ai → 设置 → 帐户 → 活跃会话** —— 撤销归属地与静态出口不符的旧会话，在专线下重新登录。
3. **Claude → Settings → Privacy** —— `Location metadata` 与 `Help improve our AI models` 均关闭。
4. **朋友那台 Mac 上的 Shadowrocket 建议卸载**（当前未连接所以不阻塞，但属定时炸弹）；`GOGO` 那个 VPN 配置问清用途，不用就删；**Cisco AnyConnect 可保留**，但要告知：**连公司 VPN 时专线会失效**，断开即恢复。
5. **日常三红线** —— 不跑第二个 VPN；Clash 保持规则模式；**先开 Clash，再开 Claude**。
